# 產品規格書 (PRD)：食物的決策輪盤

## 一、 專案概述
1. 產品名稱： 食物的決策輪盤

2. 核心宗旨： 專為「選擇困難症」與「月底荷包乾癟者」設計的惡搞型互動網頁。表面上提供可愛的選餐體驗，實則透過後台邏輯對使用者的預算與任性程度進行「無情嘲諷與干預」。

3. 技術需求： HTML5, CSS3 (Flexbox/Grid, Keyframe Animations, Filter), Vanilla JavaScript (含 Web Speech API 語音合成、Web Audio API 音效)。

## 二、 視覺風格與 UI 設計規範 (UI/UX Design)
### 1. 色彩計畫（馬卡龍糖果色系）：

 (1) 背景主色：柔和漸層或純色拼接（淺藍 #A2D2FF、淺粉 #FFAFCC、淺紫 #CDB4DB、奶油白 #FFF9F5）。

 (2) 轉盤指針：高對比度的「純黑色 #000000」，確保在糖果色背景中極度顯眼，為後續的「斷裂動畫」做視覺鋪墊。

 (3) 警告彈窗（惡搞階段）：高飽和警示紅 #FF0033、黑底白字，與前期的可愛風格形成強烈反差。

### 2. 字體與元件風格：

  (1) 採用圓體字（如粉圓體、圓體-繁），按鈕與對話框皆具備大圓角（border-radius: 16px ~ 24px）與可愛的立體陰影。

## 三、 系統預設資料與自訂功能 (Data & Customization)
### (一)預設餐點資料庫（含預設價格區間）：
#### 1.系統內建多組常見餐點及預設花費（用於判定是否超支），例如:
陽春麵 (NT$ 45)、滷肉飯 (NT$ 50)、超商御飯糰 (NT$ 35)、營養便當 (NT$ 100)、迴轉壽司 (NT$ 300)、精緻火鍋 (NT$ 500)、高檔燒肉 (NT$ 1000)。

#### 2.自訂餐點面板（CRUD 功能）：
(1)提供一個收合式的「編輯菜單」面板，使用者可隨時：

． 新增： 輸入「餐點名稱」與「預估價格(NT$)」。

． 編輯： 修改現有輪盤/卡牌上的餐點名稱與價格。

． 刪除： 移除不想看到的品項（系統需限制最少保留 2 個品項）。

註：為了觸發「預算不足」的惡搞機制，輪盤/卡牌上的項目會混合「符合預算」與「超出預算」的品項（若使用者只輸入極低金額，系統仍會保留高價品項在轉盤上供誤踩）。

## 四、 互動流程與功能邏輯 (User Flow & Logic)
### 階段 1：狀態輸入與防呆機制
#### 1.輸入元件：
(1)飢餓程度： 滑桿（Range Slider）或下拉選單，數值 1 ~ 10 分（可連動微調介面文字，例如 10 分時提示「快餓扁了」）。

(2)錢包餘額： 數字輸入框（Number Input），單位 NT$，限制輸入 >= 0 的整數。

(3)防呆與解鎖：在「錢包餘額」尚未輸入有效數字前，下方的模式選擇區與啟動按鈕呈禁用狀態（Disabled，半透明且不可點擊），並顯示提示文字：「⚠️ 請先輸入餘額才能啟動命運喔！」。

### 階段 2：決策模式選擇
當輸入完成後，畫面順暢展開（或彈出）模式選擇區，提供兩張大型可愛圖片按鍵：

#### 1. 【命運輪盤模式】按鍵：

． 視覺：淺藍色底（#BDE0FE），中央有可愛風格的輪盤插畫。

． 互動：滑鼠懸停（Hover）時觸發 transform: scale(1.05) 放大動畫與柔和陰影。

#### 2.【幸運翻牌模式】按鍵：

． 視覺：淺粉色底（#FFC8DD），中央有一張可愛風格的卡牌插畫。

． 互動：滑鼠懸停（Hover）時觸發 transform: scale(1.05) 放大動畫與柔和陰影。

### 階段 3：執行決策與「後台無情干預」
根據使用者選擇的模式，切換主畫面視圖：

#### 模式 A：命運輪盤

． 畫面中央顯示巨大可愛轉盤，正上方固定一個明顯的黑色指針，下方配置「啟動命運輪盤」按鈕。

． 點擊按鈕後，輪盤開始旋轉（CSS transform: rotate() 搭配貝茲曲線減速），約 3~4 秒後停下。

#### 模式 B：幸運翻牌

． 畫面中央顯示 6 張背面朝上的可愛卡牌（3x2 排列）。

． 使用者直接點擊任一張卡牌，觸發 3D 翻牌動畫（CSS rotateY(180deg)），背面翻開顯示餐點名稱與價格。

#### 結果判定與彈窗邏輯（兩種模式共用）：
JavaScript 取得抽中的餐點價格 itemPrice 與使用者輸入的餘額 userBalance 進行比對：

#### 情況 1：預算不足 (itemPrice > userBalance)

． 跳出嘲諷對話框：「哈哈你預算不足，沒辦法吃太貴的食物！」

． 對話框按鈕：僅顯示 1 個按鈕 【再轉一次】（卡牌模式可顯示為【再抽一次】）。

註：因預算不足而重抽，不計入「任性重轉次數」，或可視設計決定是否計入。建議僅在「吃得起卻嫌棄」時累加，嘲諷感更精準。

#### 情況 2：預算足夠 (itemPrice <= userBalance)

． 跳出祝賀對話框：「恭喜你可以去吃飯啦！（抽中：XXX）」

． 對話框按鈕：顯示 2 個按鈕：

【噢耶！終於可以吃飯啦】 ➔ 點擊後撒紙花特效，結束流程，祝用餐愉快。

【我不滿意】 ➔ 點擊後關閉彈窗，準備重選，並將任性重轉計數器 count 加 1。

## 五、 核心靈魂惡搞：強行重轉與指針斷裂機制 (The Gag Feature)
### 1. 觸發條件
宣告全域變數 let retryCount = 0;。

當使用者抽中預算內的食物，卻點擊「我不滿意」並嘗試進行第 3 次重轉 / 重抽（即 retryCount >= 3 且再次點擊啟動或翻牌）時，立即攔截正常流程，觸發以下「崩潰劇本」。

### 2. 崩潰劇本演出流程（依序執行）
#### (1)指針劇烈抖動與斷裂（0.0s ~ 1.2s）：

． (若在翻牌模式，畫面自動強制切回或浮現中央大輪盤與黑色指針，或讓黑色指針直接搭配卡牌碎裂)。

． 輪盤本體完全不轉動。

． 上方的「黑色指針」套用劇烈顫抖的 CSS Keyframes 動畫（高頻率左右搖晃）。

． 播放清脆的「啪！」斷裂音效（透過 Web Audio API 合成或載入音效）。

． 原本的黑色指針 DOM 元件替換為「斷裂鋸齒狀、向下垂頭傾斜 45 度」的損壞指針視覺外觀（並帶有掉落搖晃的物理擺動感）。

#### (2)全畫面黑白濾鏡與鎖定（1.2s）：

． 整個網頁背景與輪盤瞬間套用 filter: grayscale(100%) contrast(120%) 黑白高反差濾鏡（僅保留警告彈窗為鮮紅色）。

． 畫面上所有按鈕、輸入框、卡牌全面鎖定（pointer-events: none / disabled），使用者無法再做任何操作。

#### (3)紅色震撼警告彈窗（1.2s 同步跳出）：

． 畫面正中央以劇烈震動效果彈出巨大的「黑紅配色警告視窗」：

主標題（巨大粗體字）： 「醒醒吧！你的荷包不允許你這麼任性！」

副標題： 「因為你太厚臉皮一直重轉，輪盤指針已經氣到自斷了。乖乖接受命運，去吃泡麵或喝西北風吧！」

#### (4)語音與警報聲放送（Web Speech API）：

． 先觸發一段刺耳的蜂鳴警報聲（Web Audio API 產生短促 Sine/Sawtooth 波）。

． 緊接著呼叫瀏覽器內建 window.speechSynthesis（語音合成 API），以冷酷、無情的語氣（調整 pitch 與 rate）大聲朗讀出彈窗上的文字：「醒醒吧！你的荷包不允許你這麼任性！
乖乖去吃泡麵或喝西北風吧！」
